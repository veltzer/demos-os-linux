# TOFIX

Findings from a code scan on 2026-10-04.

## High

- `src/include/us_helper.h:167` - `struct linux_dirent` declares `char* d_name`, but the kernel record has the name bytes inline (flexible array). `src/examples/filesystem/dir_getdents.cc:73` prints `d->d_name` with `%s`, so it treats the first 8 name bytes as a pointer, and the demo segfaults on any directory (verified: `dir_getdents.elf /tmp` exits 139). Change the field to `char d_name[]` (or `char d_name[1]` for C++) and print its address. `d_ino` at `dir_getdents.cc:68` is also unsigned but printed with `%8ld`.
- `src/include/proc_utils.h:113` - `proc_print_mmap_self_filter()` loops on `while (CHECK_NOT_M1(read_size=getline(...)))`. At EOF `getline` returns -1, so every caller aborts at the end of `/proc/self/maps` (verified, exit 255). That hits `proc_print_mmap_self_only()` and the 5 examples that call it (e.g. `src/examples/stack/find_stack_start.cc`, `src/examples/dynamic_linking/pie.cc`). Loop on `!= -1` the way `proc_print_mmap_self()` at line 84 does.
- `src/include/err_utils.h:201` - `error_get_by_val()` calls `err(-1, "bad error value %d")` when the value is not in `err_tbl`. `handle_error()` calls it at line 242 for every errno-style check, so a failure with `errno==0` (EOF, or `system()` returning non-zero through `CHECK_ZERO(system(str))` at `src/include/multiproc_utils.h:99`, e.g. a `grep` that finds nothing in `proc_print_mmap`) kills the program with exit 255 before the diagnostic finishes. Errnos missing from the table (`EOWNERDEAD`, `ENOTRECOVERABLE`, `EHWPOISON`, `ERFKILL`) fail the same way. Make it return `"UNKNOWN"`, not exit, and add the missing entries.
- `scripts/ci_image_build.py:15` - triggers `gh workflow run image.yml`, but there is no `.github/workflows/image.yml`: the image is now the `image` job inside `.github/workflows/cicd.yml`. The script always fails. Point it at `cicd.yml` (it has `workflow_dispatch`, and a dispatch run always rebuilds) and fix the docstring, or delete the script.

Since `cicd.yml:45` gives every image push its own immutable `run-<id>-<attempt>` tag, which never moves, nothing ever becomes orphaned. The script never prunes, and run-scoped versions pile up on GHCR forever. Teach it to expire old `run-*` tags (e.g. keep the last N runs plus `latest`).
- `src/include/proc_utils.h:178` and `:189` - `get_thread_name_proc*()` call `fread(name, len, 1, fp)`. `comm` is shorter than `len`, so `fread` returns 0 and the buffer is left without a NUL and with the trailing newline. `src/examples/pthreads/core/names.cc:82` then prints it with `%s` and reads uninitialized stack. `CHECK_NOT_NEGATIVE` on a `size_t` can never fire either. Use `fgets`, strip the `\n`, and check the result.
- `src/examples/pthreads/core/names.cc:103` and `:131` - the worker unlocks `start_mutex`, which the main thread locked (line 116), and main unlocks `end_mutex`, which the (already joined) worker locked (line 104). Unlocking a default mutex you do not own is undefined behaviour, and lines 132-133 then destroy mutexes in that state. Use semaphores or a `pthread_barrier_t` for the handshake.
